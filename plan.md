# План: выдача JWT при регистрации и входе

## Цель

После успешной регистрации или входа пользователь получает JWT и считается вошедшим в аккаунт. Проверка JWT на защищённых маршрутах будет реализована отдельно через middleware.

## Шаги

1. **Подключить JWT-библиотеку**
   - Добавить `firebase/php-jwt` через Composer.
   - Подключить Composer autoloader в `backend/src/index.php`.

2. **Настроить секрет JWT**
   - Сгенерировать случайный секрет достаточной длины.
   - Добавить `JWT_SECRET` в локальный `backend/.env`.
   - Убедиться, что секрет не попадёт в Git; в `backend/.env.example` оставить только пример настройки.
   - Организовать чтение `JWT_SECRET` приложением наряду с настройками базы данных.

3. **Реализовать создание токена**
   - Подписывать токен безопасным алгоритмом, например `HS256`.
   - Добавить claims с ID пользователя (`sub`), временем выдачи (`iat`) и истечения (`exp`).
   - Не помещать пароль или его хэш в токен.

4. **Выдавать токен после регистрации**
   - После успешного создания пользователя сгенерировать JWT.
   - Вернуть токен, тип `Bearer`, срок действия и безопасные данные пользователя.

5. **Реализовать вход**
   - Добавить `POST /api/auth/login`.
   - Найти пользователя по логину через существующий `UserRepository::findByLogin()`.
   - Сверить пароль с сохранённым хэшем через `password_verify()`.
   - При успешной проверке выдать JWT того же формата, что и при регистрации.
   - При неверном логине или пароле вернуть `401 Unauthorized` с одинаковым сообщением.

6. **Подключить маршрут входа**
   - Зарегистрировать `POST /api/auth/login` в `backend/src/index.php`.
   - Оставить регистрацию и вход публичными; проверку JWT для защищённых маршрутов добавить на следующем этапе.

7. **Проверить через Thunder Client**
   - Зарегистрировать нового пользователя и проверить ответ `201` с токеном.
   - Войти с теми же учётными данными и проверить получение токена.
   - Проверить неверный пароль: ожидается `401` без токена.
   - Убедиться, что ответ не содержит пароль или хэш пароля.

# План: первый вертикальный срез «Веб-Дозора»

## Цель

Добавить поверх главной страницы запускаемый игровой overlay с двумя базовыми типами угроз:
обычным баннером, который закрывается кнопкой, и файлом-трояном, который нужно перетащить
в зону карантина.

## Этапы

1. **Подготовить структуру компонентов**
   - Создать отдельные Vue-компоненты для обычного баннера, файла-трояна и игрового overlay.
   - Передавать действия компонентов через типизированные props и emits.

2. **Сделать обычный баннер**
   - Показывать заголовок, описание и кнопку закрытия.
   - Закрывать баннер по честному крестику.
   - Считать клик по опасной области промахом и сообщать об уроне overlay.
   - Добавить анимацию появления и визуальный стиль вредоносного окна.

3. **Сделать файл-троян**
   - Отображать его как draggable-файл без кнопки закрытия.
   - Обрабатывать `dragstart`, `dragend` и сброс в карантин.
   - При обычном клике сообщать об уроне.
   - Добавить ограниченный таймер: истечение времени заражает систему.

4. **Собрать игровой overlay**
   - Накрывать основную страницу полупрозрачным слоем.
   - Показать стартовый экран с кнопкой запуска.
   - После запуска отображать XP, трафик, число пойманных угроз и зону карантина.
   - Подключить оба типа угроз и кнопку повторного появления угроз.
   - Обновлять игровой статус и сообщения после действий игрока.

5. **Подключить к главной странице**
   - Добавить overlay в `HomePage.vue`, не меняя маршруты и существующие страницы.

6. **Проверить вертикальный срез**
   - Запустить type-check и production build.
   - Проверить, что приложение собирается и существующая навигация не затронута.
