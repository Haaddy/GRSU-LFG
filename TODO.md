# План задач проекта GRSU-LFG

## 1. Backend — часть 1: основная архитектура

**Ответственный:** разработчик Frontend + Backend.

- [ ] Настроить структуру backend: controllers, services, repositories, models, middleware, validators, exceptions.
- [ ] Настроить bootstrap-файл приложения и загрузку `.env`.
- [ ] Настроить подключение к PostgreSQL и Composer autoload.
- [ ] Завершить Router.
- [ ] Добавить поддержку GET, POST, PATCH, PUT и DELETE.
- [ ] Добавить динамические параметры маршрутов, например `/events/{eventId}`.
- [ ] Добавить middleware для отдельных маршрутов.
- [ ] Разделить публичные и защищённые маршруты.
- [ ] Добавить обработку ошибок `404`, `405` и `500`.
- [ ] Добавить единый JSON-формат успешных ответов и ошибок.
- [ ] Создать Request/Response helpers для JSON, query-параметров, route-параметров и авторизованного пользователя.
- [ ] Создать базовые исключения: Validation, Authentication, Authorization, NotFound и Conflict.
- [ ] Создать базовый механизм валидации входных данных.
- [ ] Завершить регистрацию и вход пользователя.
- [ ] Завершить JWT-авторизацию.
- [ ] Добавить `AuthMiddleware`.
- [ ] Добавить получение текущего пользователя из JWT.
- [ ] При необходимости добавить `RoleMiddleware`.
- [ ] Проверить срок действия и payload JWT.
- [ ] Не возвращать `password_hash` в API-ответах.
- [ ] Подготовить базовые контроллеры:
  - `AuthController`;
  - `UserController`;
  - `EventController`;
  - `TeamController`;
  - `ParticipationController`;
  - `JoinRequestController`;
  - `InvitationController`;
  - `StatisticsController`.
- [ ] Зарегистрировать основные API-маршруты для будущей бизнес-логики.
- [ ] Добавить временные ответы-заглушки для ещё не реализованных endpoints.
- [ ] Подготовить API-контракты для остальных разработчиков.
- [ ] Написать архитектурные тесты для Router, JWT, middleware и формата ошибок.
- [ ] После готовности логики заявок подключить Observer/EventDispatcher.
- [ ] Подготовить события для заявок, приглашений и изменений состава команды.
- [ ] В конце добавить основу для уведомлений, не связывая Observer напрямую с контроллерами.

### Мероприятия

- [ ] Добавить серверную проверку прав организатора.
- [ ] Добавить проверку названия, дат, лимитов участников и команд.
- [ ] Добавить статусы мероприятия: upcoming, active, completed.

### Команды

### Заявки на вступление

- [ ] Реализовать создание заявки в команду.
- [ ] Запретить повторную активную заявку.
- [ ] Проверять наличие свободных мест.
- [ ] Ограничить просмотр заявок капитаном команды.
- [ ] Реализовать принятие заявки.
- [ ] Реализовать отклонение заявки.
- [ ] При принятии добавлять пользователя в `team_members`.

### Приглашения

- [ ] Проверять, что пользователь не состоит в другой команде мероприятия.

### Участники команд

- [ ] Реализовать список участников команды.

- [ ] Реализовать статистику мероприятия.
- [ ] Реализовать `GET /api/dashboard` с агрегированными данными пользователя.

### Уведомления и надёжность

- [ ] Подключить Observer к созданию, принятию и отклонению заявок.
- [ ] Подключить Observer к приглашениям и изменениям состава команды.
- [ ] При необходимости создать таблицу `notifications`.
- [ ] Реализовать API списка уведомлений и отметки уведомления прочитанным.
- [ ] Использовать транзакции для создания команды, записи, принятия заявок и приглашений.
